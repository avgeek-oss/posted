Deploy Posted on a server already registered with your Towbar installation. You need a Git repository for the deployment files and separate domains for Posted and its API.

## 1. Add the deployment files

Copy the YML files listed into your deployment repository in the same folder structure and update them as required based on the instructions below.

Replace the IP address, TLS mode, and domains as required. The required env variables need to be added to the runtime secrets based on the requirements. The example already has commented-out variables but do refer to the latest [provider configuration docs](/providers) for direct env variables as it might change with different Posted versions.

## 2. Connect the repository

Add your deployment repository as a source in Towbar, map `production` to your deployment branch and sync it. Review the three services and PostgreSQL datastore.

## 3. Add runtime values

Generate separate values for the database password and `POSTED_SECRET`:

```sh
openssl rand -hex 32
```

Save these values in Towbar:

| Workload       | Runtime values                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| PostgreSQL     | `POSTGRES_USER=posted`, `POSTGRES_DB=posted`, and your generated `POSTGRES_PASSWORD`.                       |
| API and worker | The same `DATABASE_URL`, `POSTED_SECRET`, `POSTED_WEB_URL` and `POSTED_API_URL`. Set `NODE_ENV=production`. |
| UI             | `POSTED_API_URL` and `NODE_ENV=production`.                                                                 |

Use `postgres://posted:YOUR_DATABASE_PASSWORD@posted-postgres:5432/posted` as the database URL. Replace the password placeholder privately. Set `POSTED_WEB_URL` to your UI origin and `POSTED_API_URL` to your API origin.

Fill in the optional keys you uncommented using [provider setup](/providers) and [Configuration](/configuration). Towbar requires a value for every uncommented key.

## 4. Deploy Posted

Deploy PostgreSQL first, then API, worker and UI. Wait for each workload to become ready before continuing. The API prepares the database automatically. Only API and UI need public domains; worker and PostgreSQL stay private.

The examples keep deployment manual. Start each deployment after saving its runtime values.

## 5. Create your team

Open the API startup log in Towbar and find the installation setup secret. Open your Posted URL, enter the secret and create the first administrator. Keep the setup secret private.

Next, [connect a social account](/connections) and [compose your first post](/composer). Follow [Backup and recovery](/backup) and [Upgrades](/upgrades) to maintain your installation.
