Configuration belongs in the operator's private environment, not in a client bundle or image. The API and worker share the database, stable secret, public origins, provider settings and private storage credentials. The UI receives only the public API and storage origins.

| Setting             | Purpose                                                                              |
| ------------------- | ------------------------------------------------------------------------------------ |
| `DATABASE_URL`      | PostgreSQL URI. Use a hostname reachable from the containers.                        |
| `POSTED_SECRET`     | At least 32 random characters; protects sessions and encrypted provider credentials. |
| `POSTED_WEB_URL`    | Exact public HTTPS UI origin, without a path or trailing configuration data.         |
| `POSTED_API_URL`    | Separate public HTTPS API origin used for API, MCP and provider callbacks.           |
| `POSTGRES_PASSWORD` | Required only for bundled PostgreSQL; use a random alphanumeric value.               |

## Social providers

Add the environment variables from the guide for each provider you want to connect: [X](/providers/x), [Threads](/providers/threads), [LinkedIn](/providers/linkedin), [LinkedIn Pages](/providers/linkedin-pages) or [Bluesky](/providers/bluesky). A provider appears in **Add connection** once all its required settings are present.

Use the same provider settings on the API and worker. The UI does not need provider credentials. Restart the API and worker after saving changes.

## Towbar

Social provider credentials are optional. When enabling a provider, add its complete set of environment variables to both the API and worker runtime secrets. Towbar passes configured runtime secrets even when the manifest does not list them as required.

## SMTP

Connect an email service so Posted can send team invitations, password resets and other account emails. Use the SMTP details from your email provider. Leave these settings blank if you do not want to send email.

```dotenv
POSTED_SMTP_HOST=smtp.example.com
POSTED_SMTP_PORT=587
POSTED_SMTP_SECURE=false
POSTED_SMTP_USER=posted@example.com
POSTED_SMTP_PASSWORD=YOUR_SMTP_PASSWORD
POSTED_SMTP_FROM="Posted <posted@example.com>"
```

Verify your sender domain with your email service. Set these values on the API service.

## S3 source

Leave the complete storage group blank to disable uploads.

Use a private S3-compatible bucket, such as Cloudflare R2. Create an object read/write credential limited to that bucket. Keep it in the API/worker runtime environment; the UI must not receive it.

Set these values together:

```dotenv
POSTED_S3_ENDPOINT=https://YOUR_ACCOUNT_ID.r2.cloudflarestorage.com
POSTED_S3_REGION=auto
POSTED_S3_BUCKET=posted-data
POSTED_S3_ACCESS_KEY_ID=YOUR_BUCKET_SCOPED_KEY
POSTED_S3_SECRET_ACCESS_KEY=YOUR_BUCKET_SCOPED_SECRET
```

Use your storage service's correct endpoint and region. R2 uses `auto`; other providers may require a region name. Replace placeholders privately.

### CORS

Allow the exact UI origin to PUT and GET signed objects. Expose ETag and allow headers used by S3 signing. For R2:

```json
[
  {
    "AllowedOrigins": ["https://posted.example.com"],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

Do not enable a public bucket domain. A successful upload in the UI confirms CORS and signing; container health alone does not.
